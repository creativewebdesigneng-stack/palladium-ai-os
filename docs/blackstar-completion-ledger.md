## How to mark an item complete

An item starts OPEN. Record the actual files/PR/migrations, CI on the exact feature head, merge SHA, production deployment ID and matching SHA, and—where applicable—signed-in real-provider acceptance evidence. A READY deployment alone is not proof of a business workflow, connected API, model inference, external side effect or independent certification. Use BLOCKED_EXTERNAL only when a real provider account, qualified authority, paid plan, mobile hardware or operator action is required. Never substitute a fake result or silently mark a provider-gated capability complete.

The separate [operator verification queue](blackstar-user-verification-queue.md) contains ONLY checks requiring the owner's action. Anything engineering can inspect, implement, test, deploy or observe should stay here, not be handed to the owner. Never ask for passwords, payment-card details or API keys in a chat; use the provider's own consent flow or the server-side secret manager.

**Progress accounting:** The code/deployment slice may be complete while end-to-end acceptance is pending. Do not call that feature 100% until the acceptance evidence exists. Percentages are optional only when scoped, measured against a written denominator, and distinguish unverified work from completed work. Do not treat the overall platform as a simple average of unrelated modules.
