## Repair and limits

Both dispatchers now request the inserted execution ID and require a successful
returned row before acknowledging tool success. Database errors, empty returned
rows and thrown transport errors return `TOOL_EXECUTION_EVIDENCE_UNCONFIRMED`.
The handler is not repeated, provider output is not presented as confirmed
success, and the diagnostic explicitly warns that the action may already have
occurred (`retry_safe:false`). Database/transport exception details are withheld.

This is an acknowledgement safeguard, not an atomic side-effect transaction or
an exactly-once executor. A timed-out response can leave a real ledger row or a
real external action despite an unconfirmed response. Operators must inspect
the task/provider before retrying. Failed/denied attempts remain best-effort
logged; this change does not guarantee database availability or stop a later
model from independently requesting another action. No schema changes.
